# Phase 2 VST3 ↔ CLAP 语义映射

每个 Phase 2 host-facing 能力在两种格式落地时，本表记录语义差异与降级行为。
"降级"指一种格式缺少对应概念时 SunMao 统一 API 的行为；严禁静默丢事件。

| 能力 | SunMao API | VST3 | CLAP | 差异与降级 |
|---|---|---|---|---|
| transport/timing | `ProcessContext` 的 `tempo`/`is_playing`/`is_recording`/`is_loop_active`/`sample_pos`/`time_signature`/`song_pos_beats`/`song_pos_seconds`/`bar_start_beats`/`bar_number`/`loop_beats`（M1 落地） | `ProcessData.processContext`（state flags 标记各字段有效性） | `clap_process.transport`（`clap_event_transport`，flags 同样按位标记） | 两侧字段均可缺失，统一 API 一律 `Option`，`None` 表示"宿主未提供"而非 0。单位已归一：CLAP beattime 定点（`CLAP_BEATTIME_FACTOR`）与 VST3 `TQuarterNotes` 都换算为**四分音符** `f64`。宿主完全不给 transport（CLAP `transport` 为 NULL、VST3 `process_context` 为 NULL）时全部音乐字段为 `None` 且 `is_playing` 保持 true。测试：`clap_transport_fields_reach_the_plugin`、`vst3_transport_fields_reach_the_plugin`、两侧 `a_host_without_a_*_leaves_every_musical_field_absent` |
| bar 序号 | `ProcessContext::bar_number` | 无对应字段（只有 `bar_position_music`，小节的音乐起点） | `clap_event_transport.bar_number` | **VST3 降级为 `None`**；`bar_start_beats` 两侧都可用，需要序号的插件应改用它或自行累计。测试：`vst3_transport_fields_reach_the_plugin` 显式断言 `bar_number == None` |
| loop 区间 | `ProcessContext::loop_beats`（四分音符） | `cycle_start_music`/`cycle_end_music` + `kCycleValid`/`kCycleActive` | `loop_start_beats`/`loop_end_beats` + `CLAP_TRANSPORT_IS_LOOP_ACTIVE` | 两侧一致：loop 未激活或区间非法（`end <= start`、非有限）时为 `None`，绝不下发负长度区间。CLAP 另有秒制 loop 字段，统一 API 只承诺 beats（两格式均原生提供），秒制保留在 `clap_rs::Transport::loop_seconds`。测试：`loop_region_requires_an_active_loop_and_a_sane_range`、`cycle_region_requires_an_active_cycle_and_a_sane_range` |
| 秒制位置 | `ProcessContext::song_pos_seconds` | 无秒字段，由 `project_time_samples / sample_rate` 推导 | `song_pos_seconds`（定点） | VST3 侧为推导值而非宿主原值；`sample_rate <= 0` 时 `None` |
| latency | `SunmaoPlugin::latency_samples()`（M2 落地） | `IAudioProcessor::getLatencySamples`，变更需 `IComponentHandler::restartComponent(kLatencyChanged)` | `clap.latency` 扩展 + `host_latency.changed()`（只能在重启/去激活窗口生效） | 变更通知时机不同，统一 API 因此约定"**仅在非 processing 状态可变**"：`initialize` 或 `set_render_mode` 里改，processing 期间必须恒定。**Phase 3 M1 修正的实现缺陷**：CLAP backend 的 `activate` 会把插件 `take()` 进 audio processor，原实现的 `latency()`/`tail()` 只看 `self.plugin.as_ref()` 并 `unwrap_or(0)`，因此**在插件激活期间（正是宿主真正查询的时刻）一律上报 0**——宿主会据此不做任何延迟补偿、并可能切掉尾音；VST3 backend 直接持有插件故无此问题，两格式行为分叉。现改为在 `activate` 移交所有权前缓存（此时 `initialize` 已跑完，值反映激活采样率），激活期间回落到缓存值。该缺陷由 Phase 3 M1 第 3 项新增的 runner 宿主侧断言发现——既有单测只覆盖了未激活状态。测试：`latency_and_infinite_tail_reach_the_vst3_contract`（走真实 `IAudioProcessor` vtable）、`latency_and_infinite_tail_reach_the_clap_contract`、`latency_and_tail_survive_activation`（激活期间仍可读）、runner 的 `latency_tail`（对 Tempo Delay 断言非零：两格式均读到 221 samples ＝ 44.1kHz 下 5ms lookahead，且各自使用本格式的无限尾音魔数 `i32::MAX`/`u32::MAX`） |
| tail | `SunmaoPlugin::tail() -> TailLength{None,Samples(u32),Infinite}`（M2 落地） | `getTailSamples`：`kNoTail`=0，`kInfiniteTail`=`u32::MAX` | `clap.tail`：≥`i32::MAX` 即视为无限 | 两格式的"无限"是不同魔数，统一 API 用枚举表达，backend 负责编码。**有限 tail 必须被夹到魔数之下**（VST3 夹到 `kInfiniteTail-1`，CLAP 夹到 `i32::MAX-1`），否则一个恰好等于魔数的有限值会被宿主静默当成无限尾音。测试：`a_finite_tail_never_collides_with_the_infinite_encoding`、`a_finite_clap_tail_never_reaches_the_infinite_threshold` |
| offline render | `SunmaoPlugin::set_render_mode(RenderMode{Realtime,Offline})`（M2 落地） | `ProcessSetup.process_mode`（`kRealtime`/`kPrefetch`/`kOffline`），由 `setupProcessing` 下发 | `clap.render` 扩展的 `set()` | VST3 的 `kPrefetch` 与任何未知模式都映射为 `Realtime`（较严格的契约）；两侧都只在非 processing 状态下发，因此插件可借此改 latency。CLAP 侧 `set_render_mode` 经 `catch_unwind` 包裹，插件 panic 转为 `false` 而非跨 ABI 展开。测试：`vst3_rs::RenderMode::from_process_mode`、fixture 的 `offline_rendering_doubles_the_reported_lookahead` |
| 多 bus/sidechain | `SunmaoPlugin::input_buses()`/`output_buses() -> Vec<BusInfo>`，`BusInfo::{main,sidechain}`，`BusRole::{Main,Sidechain}`；处理侧 `AudioBuffer::{num_input_buses,input_bus_channels,input_bus}`（M3 落地） | `getBusCount/getBusInfo/setBusArrangements`；`BusRole::Sidechain → PortType::Aux → BusTypes::kAux`；speaker layout 只应用于 main bus，aux 由通道数推断 | `clap.audio-ports`：无 aux 概念，`BusRole::Main → is_main=true`，sidechain 即 `is_main=false` 的普通端口 | 声明的 bus 是**通道拓扑的唯一真相**：两个 backend 的扁平通道总数都取自 bus 声明之和，因此插件加 sidechain 只需覆写 `input_buses()`。默认实现由 `input_channels()`/`output_channels()` 推导单 main bus，Phase 1 插件行为不变。宿主未连接某 bus 时 `input_bus_channels()` 返回 `None`（而非 panic 或读到别的 bus 的数据），插件可据此回落。测试：`input_bus_bounds_split_the_flat_channel_list`、`an_absent_bus_reads_as_empty_rather_than_panicking`、fixture 的 `the_plugin_declares_a_stereo_sidechain_bus`/`a_loud_key_ducks_a_quiet_main_signal`/`a_silent_key_leaves_a_loud_main_signal_alone` |
| bus 激活/去激活 | `SunmaoPlugin::set_bus_active(is_input, bus_index, active) -> bool`（Phase 3 M1 落地） | `IComponent::activateBus`，按 `MediaType`/`BusDirection`/index 定位 | `clap.audio-ports-activation/2` 的 `set_active(is_input, port_index, is_active, sample_size)`；`can_activate_while_processing` 固定 `false` | `bus_index` 即 `input_buses()`/`output_buses()` 的声明序号，两个 backend 都**先按声明校验索引**，越界一律拒绝（VST3 `kInvalidArgument`、CLAP `false`），插件回调只会见到真实存在的 bus。插件返回 `false` 时如实上报（VST3 `kResultFalse`、CLAP `false`），不静默接受。差异：**CLAP 多一个 `sample_size` 参数**（宿主的采样位宽），SunMao 只支持 f32 且 clap_rs 在 activate 阶段已拒绝其它位宽，故该参数在 backend 层被丢弃、不进统一 API；**VST3 的 event bus** 由 wrapper 自行接受（无插件侧状态可切），不进回调。两侧都只在插件未激活时调用，因此回调内可重配处理状态。去激活的输入 bus 仍占据 `AudioBuffer` 的通道槽位，插件应据此跳过读取而非期待 bus 消失。测试：`clap_rs::audio_ports_activation_validates_the_index_and_forwards_to_the_plugin`、`clap_rs::plugins_without_audio_ports_do_not_expose_the_activation_extension`、`vst3_rs::activate_bus_validates_the_index_and_forwards_to_the_plugin`、`vst3_rs::activate_bus_before_initialize_reports_not_initialized`、backend 的 `clap_port_activation_maps_onto_the_sunmao_bus_callback`/`clap_declares_one_audio_port_per_sunmao_bus`/`vst3_activate_bus_maps_onto_the_sunmao_bus_callback`、fixture 的 `deactivating_the_key_bus_returns_the_detector_to_the_main_path`/`activating_the_main_buses_is_always_accepted`；索引校验不变量由 proptest 钉住：`clap_rs::port_activation_forwards_exactly_the_declared_indices`、`vst3_rs::activate_bus_forwards_exactly_the_declared_indices`（任意声明拓扑 × 任意索引，含负数与越界：在范围内必转发且仅转发一次，越界必拒绝且绝不触达插件） |
| speaker layout 动态协商 | `SunmaoPlugin::bus_configs() -> Vec<BusConfig>` + `current_bus_config()` + `select_bus_config(index) -> bool`（Phase 3 M1 落地） | `IAudioProcessor::setBusArrangements`：宿主**提议**每个 bus 的 `SpeakerArrangement`，backend 按提议的通道数（位图 popcount）在 `bus_configs()` 中查找匹配项；命中即 `select_bus_config` 并 `kResultOk`，未命中 `kResultFalse` | `clap.audio-ports-config`：插件**枚举**配置、宿主按 id `select`；另实现 `clap.audio-ports-config-info/1`（含 draft-0 别名）供宿主查询未激活配置的端口 | **两格式方向相反但落到同一回调**：CLAP 是"插件列举 → 宿主选"，VST3 是"宿主提议 → 插件匹配"，因此 **VST3 宿主只能到达 `bus_configs()` 已发布的布局**——未发布的提议一律 `kResultFalse`，不静默接受后跑另一种布局。config id 即 `bus_configs()` 的下标，两侧同一编号。`bus_configs()` 为空（默认）＝不可协商，此时 CLAP **不暴露**该扩展、VST3 只接受声明布局，Phase 1/2 插件行为不变。协商成功后两侧都刷新派生状态：VST3 的 `getBusInfo`/`getBusArrangement`/`setupProcessing` 改报新通道数，CLAP 重建端口表、通道总数与 audio-thread scratch buffer（否则 mono→stereo 会用旧尺寸缓冲处理）。**限制**：只协商通道数，bus 数量不变；VST3 仅在组件未 active 时接受协商（`kResultFalse`），CLAP 由规范保证 deactivated。**顺带修正**：`clap_rs` 此前对所有端口固定上报 `port_type=stereo`，mono 布局出现后即为错报，现按通道数给 `mono`/`stereo`/null。一期只承诺 mono/stereo，surround 位图预留。测试：`clap_rs` 侧 `clap_publishes_one_config_per_sunmao_bus_config`/`clap_selecting_a_config_reconfigures_the_live_port_list`/`clap_refuses_a_config_the_plugin_rejects`/`a_plugin_without_alternatives_publishes_no_configs`、`vst3_negotiates_a_published_layout_and_reports_it_back`、`vst3_refuses_every_alternative_for_a_single_layout_plugin`、fixture `sunmao_fx_layout_gain` 的 5 个测试、跨格式可达性 proptest `a_layout_is_reachable_from_both_formats_or_neither` |
| 参数 modulation | `Event::ParamMod{id,amount,offset}` + `EventQueue::param_mods()`（M4 落地） | 无原生概念，VST3 宿主不会发送，故队列中不会出现该事件 | `CLAP_EVENT_PARAM_MOD` → `clap_rs::Event::ParamMod` → core | **modulation 与 automation 是两条独立通道**：`Event::as_param_change()` 对 `ParamMod` 返回 `None`，`param_changes()` 不含 modulation，因此 mod 绝不会流入插件 state。amount 是叠加偏移而非归一化值，只拒绝非有限值。测试：`param_mod_events_are_decoded_rather_than_dropped`、`short_expression_and_mod_events_are_rejected` |
| per-note expression | `Event::NoteExpression(NoteExpression{offset,kind,note_id,channel,key,value})` + `EventQueue::note_expressions()`；`NoteExpressionKind{Volume,Pan,Tuning,Vibrato,Expression,Brightness,Pressure,Unknown(i32)}`（M4 落地） | `kNoteExpressionValueEvent` 只携带 `type_id`/`note_id`/`value`；type id 见新增的 `vst3_sys::NoteExpressionTypeIDs` | `CLAP_EVENT_NOTE_EXPRESSION`，携带 note_id + port/channel/key | **VST3 只按 note_id 定位音符**，因此统一结构的 `channel`/`key` 是 `Option`：VST3 侧为 `None`，CLAP 侧为 `Some`。插件应优先按 note_id 匹配，退化时按 channel/key 匹配（fixture 即如此）。**VST3 没有 pressure 维度**（宿主用独立的 `kPolyPressureEvent` 传递），故 VST3 侧永不产生 `Pressure`。未知维度保留原始 id 为 `Unknown(i32)` 并照常下发，绝不丢事件。**Phase 3 M1 修正的实现缺陷（VST3 侧 expression 此前根本到不了插件）**：VST3 宿主经回调下发 expression，而 backend 原实现在回调里直接 push 进 `self.event_queue`；但 `process` 会在合并本块事件前 `self.event_queue.clear()`，**该 clear 发生在回调之后**，于是每个 VST3 note expression 都被静默丢弃——违反本文件“严禁静默丢事件”的约定。MIDI 未受影响是因为它走 `pending_midi` 暂存再合并，expression 没有对应暂存。现新增 `pending_expressions`（与 `pending_midi` 同容量策略、同 `try_reserve_exact` 预分配，故 audio callback 仍零分配），并把 param/MIDI/expression 三路按 sample offset 归并（并列时序为 param → MIDI → expression，确定性）。此缺陷 `_rs` 层与 core/fixture 两端的既有测试都测不到（vst3_rs 正确分发、core 正确处理，缺口恰在中间的 backend），正是 Phase 3 M1 第 4 项“backend 层端到端映射测试”要覆盖的位置。测试：`note_expression_events_are_decoded_rather_than_dropped`、`an_unknown_expression_dimension_keeps_its_raw_id`、backend 端到端 `raw_vst3_expression_events_reach_the_core_queue`（构造原始 `NoteExpressionValueEvent` 走真实 `IEventList`，断言 kind/note_id/value/offset、VST3 侧 channel/key 为 `None`、未知 id 保留原值，并断言与 MIDI 按 offset 交错）、`raw_clap_expression_and_mod_events_reach_the_core_queue`（原始 `clap_event_note_expression_t` 与 `clap_event_param_mod_t` 走真实 `clap_input_events_t`，断言 CLAP 侧 channel/key 为 `Some`、param mod 按数值 id 译回字符串 id、且 modulation 不出现在 automation 流）、fixture 的 `a_volume_expression_scales_only_the_addressed_voice`/`a_tuning_expression_bends_the_addressed_voice`/`an_expression_for_another_key_leaves_the_voice_untouched`/`an_unnamed_expression_dimension_is_accepted_without_effect` |
| voice-info | `SunmaoPlugin::voice_info() -> Option<VoiceInfo{active,capacity,supports_overlapping_notes}>`（M4 落地） | 无对应接口 | `clap.voice-info` 扩展 | **VST3 降级：该信息不向宿主暴露**（VST3 无对应查询点），插件实现同一方法即可，不需要格式分支。默认返回 `None`，表示"非发声类插件"。 |
| 版本化 state | `SunmaoPlugin::STATE_VERSION` 常量 + `migrate_state(from_version)` 钩子（M5 落地） | `IComponent::setState/getState` 字节流，编解码在 `vst3_rs/src/state.rs` | `clap.state` 字节流，编解码在 `clap_rs/src/ext/state.rs` | 两侧都是不透明字节流，头部结构（magic + version + count + 按参数 id 的条目）在两个格式层保持一致。**版本策略**：旧版本 state 被接受（条目按参数 id 匹配，老参数恢复、新参数留默认值），未来版本被拒绝（本 build 无法解释）。此前两侧都对版本不符直接拒绝，旧 preset 会整体丢失——这是 M5 修复的本体。增删参数不需要升版本，只有**既有参数的含义变化**才需要。测试：两侧各 `a_state_from_an_older_build_is_accepted`/`a_state_from_a_newer_build_is_rejected`/`a_foreign_magic_is_rejected`，fixture 的 `a_v1_state_leaves_the_new_parameter_at_its_documented_default` |
| preset 载入 | （M5 设计中） | program lists / `IUnitInfo`（宿主驱动） | `clap.preset-load`（宿主给路径/位置） | 模型差异大：一期统一 API 只承诺"插件侧载入回调 + 状态应用"，VST3 program list 映射为可选实现 |

## 记录规则

- 每个 milestone 落地时把对应行的"设计中"替换为最终 API 名，并补充实测差异。
- 单元/宿主测试必须覆盖表中每条降级行为；测试名写入对应行。
